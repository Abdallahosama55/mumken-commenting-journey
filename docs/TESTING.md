# Testing approach

## Philosophy

* **Test behaviour through the public seams, not implementation details.** The composer state machine is
  tested as a hook. The journeys are tested through the rendered UI by role, label and text, the way a user or
  a screen reader finds things.
* **Real data layer, no mocks of our own code.** Every suite runs the actual `InMemoryRepository` and
  `NetworkSimulator` through `createTestServices()` (zero latency, fixed clock, no automatic retries). Failure
  scenarios are produced by the same simulator reviewers use, not by stubbing functions.
* **Each requirement has a test that would fail if it regressed.** See the traceability matrix in
  [`specs/03-tasks.md`](specs/03-tasks.md).
* **Accessibility is asserted, not assumed:** axe in jsdom on every discussion state, axe in a real Chromium
  on four pages in both languages (with colour contrast), and a unit test of the design-token contrast ratios.

## Suites

| Suite | Runner | Tests | Covers |
| --- | --- | --- | --- |
| `packages/core` | Vitest | 161 | Thread building (ordering, flattening, orphans, cycles), validation (code points), language detection, dataset schema, repository (not found, idempotency, one-level replies, server validation, storage restore and corruption), network simulator (fail once/always, abort, latency with fake timers), drafts, Arabic plural rules (13 cases), dictionary parity (keys, placeholders, plural shape, no untranslated Arabic), Gregorian dates and engine parity, relative time, locale negotiation, token contrast, and the composer state machine (post, fail, retry with the same key, new key after an edit, double submit, validation, counter, replies, discard) |
| `apps/web` | Vitest + Testing Library + axe | 17 | The discussion journey: loading → threads, post + announce, failure → text kept → Retry (no duplicate), edit after failure, empty validation + focus, Ctrl+Enter, inline reply focus management (open, Esc, reopen draft, post → focus new reply), empty state, load failure + recovery, per-comment `lang`/`dir`, full Arabic, axe in four states; proxy locale negotiation and path switching |
| `apps/web/e2e` | Playwright (desktop 1280 px + Pixel 7) | 12 | Arabic browser → `/ar` → record; post + reply + reload persistence; failed post recovery; language switch keeps the draft and direction; empty / unavailable / load failure; in-browser axe (WCAG 2.0/2.1/2.2 A + AA) on four pages |
| `apps/mobile` | jest-expo + React Native Testing Library (`renderRouter`) | 10 | The real Expo Router stack: list → record, post + VoiceOver announcement, failure → Retry, validation, reply screen round trip with the draft kept, empty, unavailable, load failure + recovery, Arabic RTL with per-comment `writingDirection`/alignment/`accessibilityLanguage`, live language switch from settings keeping the draft |

**Total: 200 automated tests.**

## Running

```bash
npm test             # core + web + mobile (≈ 15 s)
npm run test:e2e     # builds the web app, starts it, runs Playwright (≈ 1 min incl. build)
npm run verify       # typecheck + lint + tests for every workspace
```

## Manual verification done

* Web: production build checked in headless Chromium at 1280 px and 390 px, in English and Arabic, with
  no console errors. Screenshots in `docs/screenshots/web-*` are generated by `e2e/screenshots.spec.ts`.
* Mobile: run in Expo Go 58 on an Android emulator (records, discussion, reply, settings, failure, Arabic
  RTL, empty). Screenshots are `docs/screenshots/mobile-*`. Findings are in DECISIONS § Limitations.
* Not done: a physical iPhone or the iOS Simulator (no Xcode on the development machine).
